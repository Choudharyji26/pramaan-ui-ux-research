# Coverage: the 34 builder screens in the split layout

One screen, two panes. Left (400px) is the chat with Pramaan: messages, the docked "Next step" card, the composer. Right is the results and actions: tab bar, one view at a time. The top bar holds the logo, breadcrumb, stage tape, Settings, Logs and Account. Open `index.html` by double-click. `index.html#s=<id>` jumps to a state. The "Screens" button (bottom left of the right panel) lists all 34 ids and two review-only demos.

Rules held on every state: exactly two scrollers (chat messages, right view); at most one `.primary-action` (the Thread: the docked card, or the interview question card's "Submit answers", or the 22b send once there is text); the right panel never has a primary button; `body[data-screen]` carries the id; a badge "maps to <id> <name>" sits top right of the right panel.

Modes: home (01, 17), new (02), handoff project (18 to 20), idea project (03 to 16), repo project (21 to 23). Tabs: Overview, Decisions, Documents, Roadmap, Build, Try it (project modes); Requests (repo); Projects (home). Tabs and tape use the same targets and states.

## Notes

- Not drawn here, by design: the density toggle and the rail collapse have no equivalent (there is no rail; the tabs and tape replace it). The Lane B Settings page (16 with "Merge automatically when the review passes" off and the repository fact) is specified in SPEC.md P.3, not drawn: 16 shows the founder fixture.
- Variants that are part of an id, not extra ids: 13 ready (`#s=13&v=ready`), 08 imported (after 20 "Use this document").
- Every flow.js toast became a chat status line. Threads that were `href="#"` in the proposal (18e, 21b, 21c, 22, 23) post "That opens GitHub in the real product. It is not part of this prototype."
- Tape and tab targets per fixture follow each screen's own links (todo: Interview 07, Roadmap 12, Build 13; test: Interview 05, Roadmap 11; ui test: Interview 06, Documents 09; Todo list: Interview 06, Roadmap 11b; test first: Build 14, Try it 15; Customer portal: Interview 20).
- Cross-fixture jumps: the tape and tabs of a screen link to that fixture's own pages, but the pages they land on belong to the screen's own fixture project (for example Overview from todo opens 03, which is the "test" project). The prototype keeps one fixture per screen id, as in the proposal.
