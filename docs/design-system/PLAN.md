## 3. Acceptance checks every builder runs

From the repo root `C:\Users\adity\Desktop\Claude Lives here\Pramaan project\Pramaan\pramaan-web`:

1. `node docs/design-system/tools/contrast.mjs` (WP1 only, must print `Failures: 0`; other WPs run it once to confirm the ladder is unchanged).
2. `node docs/design-system/tools/check-css.mjs` must print `0 failing`. It compiles every stylesheet with lightningcss (`cssModules: false`), rejects `:global {`, unbalanced `/* */`, hex or raw colour functions outside tokens.css, and `--pm-ref-*` outside tokens.css.
3. `node docs/design-system/tools/shoot.mjs <your html files>` must print `0 failing` at both 1142x732 and 1440x900. It asserts: no horizontal overflow; the rail has no scrollbar; at most one vertical scroller inside `main`; the top bar is sticky and stays at top 0 after scrolling; exactly one visible `[data-thread]` element (or none when `main[data-thread-none]` declares that nothing needs the founder), never more than one after scrolling; exactly one `h1`; every tape step is a link or `aria-disabled`; the document body does not scroll; no em dash in visible text; Schibsted Grotesk loaded; no console errors. PNGs land in `docs/design-system/shots/` for the builder to look at with the Read tool (builders must look at every PNG they produce and fix what looks wrong before handing back).
4. Manual: open the file by double-click (file:// URL) and confirm it renders without a server.

Report format for every builder and reviewer handback:

```
STATUS: done | done-with-gaps | blocked
FILES WRITTEN: absolute paths
COMMANDS RUN: each command and the last 10 lines of its output
SCREENSHOTS LOOKED AT: file names, and what was fixed after looking
GAPS: any SPEC item not met, with the reason (never silently skip)
QUESTIONS FOR THE PLANNER: only if a SPEC ambiguity blocked you
```

## 5. Review lenses (all reviewers)

1. The five laws (SPEC A.3) with the automated checks in `tools/shoot.mjs` re-run after every fix.
2. Coverage matrix rows (SPEC F) assigned to the files under review: each row must be visibly demonstrated.
3. Craft-floor bans: no eyebrow/kicker, no hero-metric template, no identical icon-heading-text card grids, no side stripes, no gradient text, no glass, no hard offset shadows, no emoji or Unicode glyph icons (SVG only), no display font in labels, no monospace as costume.
4. Founder persona vocabulary: no token, digest, repo, PRD, UAT, deploy, id in the first viewport; wire words verbatim only inside a sentence or Details; every disabled control has a reason; no em-dash; sentences under 14 words where possible.
5. Contrast: every text/background pair is one of the verified pairs in SPEC B.2; anything else is a finding.
6. Containment at 1142x732: no clipped headers, no nested scroll, rail fits, thread visible, main job starts by y = 140 (204 on the overview).
7. Direction fidelity: with content mentally removed, the five identity carriers are present and each carrier does its one job (no decorative stitches, pins or chalk).
8. Consistency across screens: identical shell markup, identical component classes, no per-screen overrides that fork a component.

Reviewers fix findings themselves in small edits (one concern per edit), re-run `check-css.mjs` and `shoot.mjs`, look at the new PNGs, and hand back the findings table with "fixed" or "left open, reason".
